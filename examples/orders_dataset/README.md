# Orders dataset (synthetic)

200 e-commerce orders generated for validating the Agentic AI Data Analyst pipeline end-to-end.

## File

`orders.csv` — 200 rows, 12 columns. Generated by `generate.py` (seeded).

## Schema

| Column | Type | Notes |
|---|---|---|
| `order_id` | string | Unique per order (ORD-NNNN) |
| `customer_id` | string | C##### |
| `order_date` | date | ISO YYYY-MM-DD, spread over 2026-01-01 to 2026-05-10 |
| `channel` | string | one of `web`, `mobile_app`, `marketplace`, `phone` — 2 rows have case-mismatched values (`Mobile_App`, `WEB`) |
| `region` | string | one of `NA`, `EMEA`, `APAC`, `LATAM` |
| `product_category` | string | one of `electronics`, `apparel`, `home_goods`, `beauty`, `books` |
| `items` | integer | order line count |
| `revenue_usd` | decimal | gross revenue before discount |
| `discount_pct` | decimal | 0.00–0.40; **3 rows are NULL** (rows 47, 113, 188 by 1-indexed seed order) |
| `revenue_after_discount_usd` | decimal | net revenue |
| `payment_method` | string | one of `credit_card`, `paypal`, `gift_card`, `bnpl` |
| `returned` | boolean | `true` / `false` |

## Seeded analytical structure

The data is constructed so a competent analysis pipeline should surface:

- **Mobile app has the highest return rate** (~18%) vs web (~10%) — 2.4× lift built into the generator.
- **Electronics is the highest-return category** (~12%) and electronics-on-mobile-app receives 15–40% discounts on ~70% of orders — these heavily-discounted electronics orders should appear as a return-rate cluster.
- **BNPL payment** is engineered with a 1.7× return-rate lift over credit card — should surface in payment-method analysis.
- **Data quality anomalies** for Phase 3 to find: 3 NULL `discount_pct` values + 2 case-mismatched `channel` values.

## Stakeholder framing for the pipeline run

- Objective: "Identify the top drivers of product returns and recommend interventions for Q3."
- Stakeholder: ops team (medium technical tolerance).
- Constraints: SQL + Python; PII not present.
